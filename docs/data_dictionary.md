# Data dictionary

Notation: **PK** primary key, **FK** foreign key, **U** unique, **IDX** indexed.
String lengths are maximums. Dates are ISO `YYYY-MM-DD`; datetimes are
timezone-naive UTC in storage (seed timestamps are fixed for reproducibility).
Enumerations are stored as strings with database-level validation.

## Identifier conventions

| Entity | Pattern | Example |
|---|---|---|
| Employee | `EMP-{6-digit}` | `EMP-000001` |
| Team | `TEAM-{3-digit}` | `TEAM-001` |
| Skill | `SKL-{3-digit}` | `SKL-001` |
| Shift template | `TPL-{3-digit}` | `TPL-001` |
| Shift instance | `SHIFT-{date}-{team-seq}-{code}` | `SHIFT-2026-10-01-001-A` |
| Shift assignment | `ASG-{6-digit}` | `ASG-000001` |
| Leave request | `LVE-{year}-{6-digit}` | `LVE-2026-000001` |
| Attendance event | `ATT-{employee-id}-{timestamp}` | `ATT-EMP-000001-20261110T060000` |
| Swap request | `SWP-{year}-{6-digit}` | `SWP-2026-000001` |
| Scheduling run | `RUN-{year}-{6-digit}` | `RUN-2026-000001` |
| Scheduling exception | `ISS-{year}-{6-digit}` | `ISS-2026-000001` |
| User | `USR-{6-digit}` | `USR-000001` |
| Coverage requirement | `CVR-{4-digit}` | `CVR-0001` |

The `SHIFT` format extends the documented `SHIFT-2026-01-01-A` with a team
sequence because each team operates its own A/B/C shift instance on a date.
Counters are zero-padded, immutable once assigned, and persisted in
`id_counters`.

## 1. Employee

| Field | Type | Req | Allowed / units | Uniqueness | Validation |
|---|---|---|---|---|---|
| employee_id | String(16) | Yes | `EMP-######` | PK | Immutable; generated by counter |
| team_id | String(16) | Yes | FK Team | — | Must exist and be active for new assignments |
| first_name / last_name | String(60) | Yes | 1–60 chars | — | Non-empty |
| email | String(160) | Yes | valid email | U | Lower-case synthetic domain; one per employee |
| phone | String(30) | No | `+91-9XXXXXXXXX` | — | Synthetic; optional |
| job_title | String(80) | Yes | role title | — | Non-empty |
| employment_type | Enum | Yes | `FULL_TIME`, `PART_TIME`, `CONTRACT`, `INTERN` | — | Drives default caps |
| hire_date | Date | Yes | not in future | — | Must be a valid date |
| status | Enum | Yes | `ACTIVE`, `ON_LEAVE`, `INACTIVE`, `TERMINATED` | — | Only ACTIVE is schedulable |
| weekly_hours_cap | Float | Yes | hours/week, >0, ≤60 | — | Default 40; hard scheduling bound |
| daily_hours_cap | Float | Yes | hours/day, >0, ≤16 | — | Overtime threshold |
| overtime_cap_weekly | Float | Yes | hours/week, 0–30 | — | Weekly overtime limit |
| min_rest_hours | Float | Yes | hours, 0–24 | — | Minimum gap between shifts |
| preferred_shift | Enum | Yes | `MORNING`, `EVENING`, `NIGHT`, `NONE` | — | Soft objective only |
| notes | Text | No | free text | — | No confidential data |
| created_at / updated_at | DateTime | Yes | UTC | — | Audit timestamps |

Cardinality: Employee N:1 Team; N:M Skill via `employee_skills`; 1:N
assignments, leave, attendance, availability, manager roles; 0..1 user login.

## 4. ShiftTemplate

Cardinality: 1:N dated shifts and coverage requirements.

## 5. Shift (supporting instance entity)

| Field | Type | Req | Allowed / units | Uniqueness | Validation |
|---|---|---|---|---|---|
| shift_id | String(40) | Yes | `SHIFT-date-team-code` | PK | Immutable |
| shift_date | Date | Yes | calendar date | — | IDX |
| shift_template_id | String(16) | Yes | FK template | — | Must exist |
| team_id | String(16) | Yes | FK team | — | Must exist |
| start_at | DateTime | Yes | UTC | — | IDX; before end_at |
| end_at | DateTime | Yes | UTC | — | After start_at |
| required_staff | Integer | Yes | ≥1 | — | Total headcount requirement for the shift |
| status | Enum | Yes | `PLANNED`, `PUBLISHED`, `COMPLETED`, `CANCELLED` | — | Cancelled shifts are not scheduled |
| created_at / updated_at | DateTime | Yes | UTC | — | Audit timestamps |

Unique: `(team_id, shift_date, shift_template_id)`.

## 6. ShiftAssignment

| Field | Type | Req | Allowed / units | Uniqueness | Validation |
|---|---|---|---|---|---|
| assignment_id | String(16) | Yes | `ASG-######` | PK | Immutable |
| shift_id | String(40) | Yes | FK shift | — | Must exist; IDX |
| employee_id | String(16) | Yes | FK employee | — | Must exist; IDX |
| status | Enum | Yes | `SCHEDULED`, `CONFIRMED`, `COMPLETED`, `CANCELLED`, `SWAPPED_OUT`, `SWAPPED_IN`, `NO_SHOW` | — | IDX; inactive rows preserved |
| assignment_source | Enum | Yes | `BASELINE`, `OPTIMIZER`, `MANUAL`, `SWAP` | — | Provenance |
| assigned_at | DateTime | Yes | UTC | — | When the assignment was created |
| scheduled_hours | Float | Yes | hours, >0 | — | From template duration |
| is_overtime | Boolean | Yes | true/false | — | Derived from weekly cap at creation |
| run_id | String(24) | No | FK scheduling run | — | Null for manual/baseline |
| notes | Text | No | free text | — | Reason/history note |
| created_at / updated_at | DateTime | Yes | UTC | — | Audit timestamps |

No hard unique `(shift, employee)` constraint because cancelled/swapped-out
rows are preserved while an employee may later be re-assigned; active duplicates
are rejected by the assignment service and validation suite.

## 10. CoverageRequirement

| Field | Type | Req | Allowed / units | Uniqueness | Validation |
|---|---|---|---|---|---|
| coverage_id | String(16) | Yes | `CVR-####` | PK | Immutable |
| team_id | String(16) | Yes | FK team | — | IDX |
| shift_template_id | String(16) | Yes | FK template | — | IDX |
| skill_id | String(16) | No | FK skill | — | NULL means overall headcount |
| day_type | Enum | Yes | `ALL`, `WEEKDAY`, `WEEKEND`, `HOLIDAY` | — | Effective version selected |
| min_staff | Integer | Yes | ≥1 | — | Per skill or total |
| effective_from | Date | Yes | ISO date | — | Version start |
| effective_to | Date | No | ISO date | — | Version end |
| created_at / updated_at | DateTime | Yes | UTC | — | Audit timestamps |

Unique version key: `(team_id, shift_template_id, day_type, effective_from,
skill_id)`. The latest effective version wins; `Shift.required_staff` carries
the total headcount for the dated shift.

## Supporting entities

| Entity | Key | Purpose / notable fields |
|---|---|---|
| EmployeeSkill | PK (`employee_id`, `skill_id`) | N:M bridge; proficiency 1–5, certified, years_experience, updated_at |
| EmployeeAvailability | PK `availability_id` | effective-dated recurring weekly availability: day_of_week 0–6, is_available, available_from/to |
| TeamManager | PK `team_manager_id` | Effective-dated manager assignment; is_primary, effective_from/to |
| LeavePolicy | PK `policy_id` | leave_type U, annual entitlement, max consecutive days, document threshold, paid flag, notice days |
| LeaveApprovalHistory | PK `history_id` | append-only: from/to status, action, actor, comment, created_at |
| SwapRequest | PK `swap_id` | requester/target employees and assignments, status, agreements, manager, decision, applied_at |
| SwapApprovalHistory | PK `history_id` | append-only lifecycle: REQUESTED, TARGET_ACCEPTED, APPROVED, REJECTED, CANCELLED, APPLIED |
| SchedulingRun | PK `run_id` | scope, status, solver status, objective, assignments, gaps, duration, parameters JSON |
| SchedulingDecision | PK `decision_id` | run/shift/employee/assignment, reason, skill/availability/leave checks, evaluation JSON, score |
| SchedulingException | PK `issue_id` | issue_type, affected entities, transaction ref, severity, description, resolution, fingerprint U |
| Role | PK `role_id` | ADMIN/HR/MANAGER/EMPLOYEE, permissions JSON |
| User | PK `user_id` | username/email U, employee_id U nullable, password_hash, role FK, active, last_login |
| AuditLog | PK `audit_id` | actor, action, entity, previous/new JSON, reason, IP, timestamp; append-only |
| SystemConfig | PK `config_key` | runtime JSON value, description, updater, timestamp |
| IdCounter | PK `counter_key` | next_value, transactional identifier sequence |
